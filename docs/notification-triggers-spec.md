# Pool's Day 알림 트리거 상세 스펙 (v0.1 초안)

> 본 문서는 PUSH_POLICY.md(상위 정책)에 따라 26개 알림 트리거의 *발송 조건, 수신자, 본문, 액션*을 정의하는 운영 명세서다. 카피 문안은 v0.1 초안이며, 디자이너·운영자 검토를 거쳐 확정한다.

---

## 공통 사양

### 변수 표기

```
{nickname}      상대방 또는 본인 닉네임 (2~6자)
{pool}          수영장 이름
{date}          일정 날짜 (M월 D일 또는 내일/오늘 등 상대 표현)
{time}          일정 시간 (HH:MM)
{duration}      시간 범위 (HH:MM~HH:MM)
{count}         수치 (N명 / N건 등)
{feature_name}  기능 이름
{version}       앱 버전
```

### 액션 패턴

```
A: 0버튼 (탭 시 관련 화면 이동)
B: 1버튼 (이동 강조)
C: 2버튼 응답형 (수락/거절)
E: 이력 표시 (액션 없음, 회색 표시)
```

### 우선순위

```
P0: 법정 의무·보안 (끌 수 없음)
P1: 핵심 상호작용 (기본 ON)
P2: 중요 이벤트 (기본 ON)
P3: 부가 알림 (기본 ON, 사용자가 자주 끔)
```

# 유형 1. 사람 발신 (9개)

## 1. friend_request_received

```yaml
유형:       1. 사람 발신
우선순위:   P1
채널:       인앱 + 푸시
발송 시점:  친구 신청 수신 시 즉시
수신자:     신청 받은 사람
이미지:     신청자 프로필 사진
액션 패턴:  C (2버튼 응답형)

제목:       친구 신청이 왔어요
본문:       {nickname}님이 친구가 되고 싶어해요
푸시:       {nickname}님이 친구 신청을 보냈어요 🏊

변수:
  - {nickname}: 신청자 닉네임

액션:
  버튼1:    거절
  버튼2:    친구로 등록  (강조)

후처리:
  수락 시:  friend_request_accepted 트리거 발생 (양측)
            카드 → "친구가 됐어요" 회색 처리
  거절 시:  friend_request_rejected 트리거 (본인 이력)
            카드 → "거절했어요" 회색 처리
            신청자에게는 무알림

만료 처리:  신청자가 신청 취소 → 카드 비활성화 + "취소된 신청"
끌 수 있음: ✅ (친구 관련 토글)
```

# 검토 필요 사항

## 1. 마케팅 카피 (16~18)
- "(광고)" 표시 위치 (제목 vs 본문)
- 변수가 매번 바뀌므로 본문 템플릿 유연성 확보 필요

## 2. 완료 프롬프트 (25)
- 빈도가 너무 잦을 수 있음 (주 3회 다니는 사용자 = 주 3회 푸시)
- *유형 결정*: 5. 환영·축하 vs 4. 자동·필수 중 어느 쪽?

## 3. 친구 일정 알림 (26)
- 케이스 A·B 둘 다 구현인지 한쪽인지
- 친구가 일정 비공개로 만들면 어떻게 처리할지

## 4. 푸시 본문 길이
- iOS 잠금 화면: 약 100자 제한
- Android: 약 80자 권장
- 현재 본문 일부는 길어서 *푸시용 짧은 버전* 별도 필요

## 5. 일정 시간 표현 통일
- "{date} {time}" vs "{date} {time}~{end_time}"
- 시간 범위 표시할지 시작 시간만 표시할지

## 6. 변수 누락 시 폴백
- {pool}이 비어있거나 삭제된 풀이면?
- {nickname}이 탈퇴 회원이면?
